# 3g. Apply formatting and style adjustments to a configuration

## What `terraform fmt` Does

`terraform fmt` переписывает файлы конфигурации в целевой директории в соответствии с **каноническим стилем** Terraform — согласованные отступы, выравнивание, пробелы. Она намеренно **с фиксированным мнением, без опций кастомизации**, потому что вся её цель — согласованность между кодовыми базами, а не личные предпочтения.

Любая конфигурация, которую Terraform сам генерирует, уже следует этому стилю — запуск `fmt` на файлах, написанных вручную, поддерживает согласованность всего.

## What It Catches vs. What It Doesn't

`fmt` парсит HCL только на предмет **проблем форматирования** — таких вещей, как недопустимые символы или некорректный синтаксис блоков, которые мешают даже понять структуру файла (например, случайный `$` там, где предполагалась интерполяция: `Name = $var.name-learn`). Она сообщает о них как об ошибках, потому что не может безопасно переформатировать код, который не может распарсить.

**Она не проверяет корректность относительно providers** — неправильные имена атрибутов, отсутствующие обязательные аргументы, несовпадение типов, циклы. Это работа `terraform validate` (3c). Рекомендуемая последовательность:

```bash
terraform fmt        # fix style / catch unparseable syntax
terraform validate   # check correctness against provider schemas
```

## Usage

```bash
terraform fmt [options] [target...]
```

По умолчанию она сканирует **текущую директорию**. В качестве цели вместо этого можно указать конкретную директорию, конкретный файл или stdin (`-`).

| Flag | Effect |
| :--- | :--- |
| `-list=false` | Не выводить список файлов с несоответствиями форматирования. |
| `-diff` | Показать diff изменений форматирования. |
| `-write=false` | Не перезаписывать файлы (подразумевается автоматически при `-check` или когда ввод из stdin). |
| `-check` | Завершается с кодом `0`, если уже отформатировано, иначе — ненулевым (и выводит список проблемных файлов) — ничего не переписывает. Полезно как gate в CI. |
| `-recursive` | Также обрабатывать поддиректории (по умолчанию выключено — обрабатывается только целевая директория). |
| `-no-color` | Отключить цветной вывод. |

## Exam Quick Facts

* `fmt` = **только стиль/форматирование** — канонические отступы/выравнивание, без проверки корректности относительно provider'а.
* Нет опций кастомизации — она намеренно с фиксированным мнением ради согласованности между кодовыми базами.
* Рекомендуемый порядок: `fmt` → `validate` → `plan` → `apply`.
* `-check` — недеструктивный, дружелюбный к CI вариант (сообщает, не переписывает).
* `-recursive` нужен, чтобы затронуть поддиректории — область действия по умолчанию — только текущая директория.
