# 3b. Initialize a Terraform working directory

## What `terraform init` Does

`terraform init` — это **первая команда, которую нужно запустить** после написания новой конфигурации или клонирования существующей. Она подготавливает рабочую директорию, выполняя по порядку:

1. **Backend initialization** — читает конфигурацию backend'а в root-модуле и инициализирует его. (Типы/конфигурация backend'ов подробно разобраны в Section 6 — эта заметка лишь отмечает, что init — это триггер.)
2. **Child module installation** — находит `module`-блоки и получает исходный код модулей.
3. **Provider plugin installation** — находит прямые/косвенные ссылки на providers и устанавливает соответствующие плагины, записывая/обновляя `.terraform.lock.hcl` (полная механика lock-файла — в 2a, эта заметка покрывает только *когда* происходит эта запись).

Запускать его **всегда безопасно повторно** — он никогда не удаляет существующую конфигурацию или state, хотя последующие повторные запуски могут выдавать ошибки, если что-то изменилось (например, backend или версии модулей), что требует явного флага для решения.

## Key Flags

| Flag | Effect |
| :--- | :--- |
| `-upgrade` | Игнорирует зафиксированные в lock-файле выборы; устанавливает новейшую версию, допустимую constraints, как для providers, так и для модулей. |
| `-backend=false` | Пропускает инициализацию backend'а. Полезно для оффлайн-валидации; некоторые другие шаги init требуют инициализированного backend'а, поэтому используйте только если директория уже была инициализирована ранее. |
| `-reconfigure` | Отбрасывает существующую конфигурацию backend'а; **не** мигрирует state. |
| `-migrate-state` | Пытается скопировать существующий state во вновь настроенный backend. |
| `-force-copy` | Подавляет запросы подтверждения `-migrate-state` (автоматически отвечает "yes"); также включает `-migrate-state`. |
| `-get=false` | Пропускает установку дочерних модулей. |
| `-plugin-dir=PATH` | Устанавливает providers только из локальной директории (одноразовый override — для регулярного использования вместо этого настройте filesystem mirror глобально). |
| `-from-module=SOURCE` | Копирует модуль в **пустую** целевую директорию перед выполнением остальной части init — сокращённый способ получить стартовую конфигурацию. |
| `-lockfile=readonly` | Подавляет изменения lock-файла; только проверяет checksums относительно уже зафиксированного. Конфликтует с `-upgrade`. |
| `-input=true/false` | Запрашивать ли недостающий ввод; `false` вызывает ошибку вместо запроса — полезно для автоматизации. |
| `-lock` / `-lock-timeout` | Управляют locking state во время связанных со state операций init. |

## Re-Running Init After Config Changes

Terraform требует повторной инициализации всякий раз, когда вы:

* Добавляете, удаляете или меняете **версию модуля или provider'а**.
* Добавляете, удаляете или меняете **backend или блок `cloud`**.
* Клонируете репозиторий с Terraform-конфигурацией впервые.

Если пропустить это, `validate`/`plan`/`apply` обнаружат это и предложат заново запустить `init` (а иногда конкретно `init -upgrade`, например, когда зафиксированная в lock-файле версия provider'а больше не удовлетворяет изменённому constraint).

## What Gets Created

* **`.terraform.lock.hcl`** — dependency lock file (полная семантика — см. 2a).
* Директория **`.terraform/`** — собственный кэш Terraform, содержащий:
  * `.terraform/modules/` — `modules.json` (отображает каждый ключ модуля, включая неявный root-модуль, на его источник и локальную директорию), а также локальные копии любых **remote**-модулей. Локальные модули берутся напрямую из настроенного пути и подхватываются сразу же при редактировании; remote-модули обновляются только через `init -upgrade` или `terraform get`.
  * `.terraform/providers/` — закэшированные бинарники provider-плагинов, разложенные по схеме `[hostname]/[namespace]/[name]/[version]/[os_arch]`.

**Никогда** не коммитьте `.terraform/` в систему контроля версий и никогда не редактируйте её содержимое вручную — она полностью управляется Terraform, и её структура может меняться между версиями.

## Exam Quick Facts

* Порядок `init`: **backend → modules → providers → lock file**.
* Всегда безопасно перезапускать; никогда не удаляет конфигурацию или state.
* `-upgrade` — единственный флаг, пересматривающий более новые версии providers/модулей относительно lock-файла.
* Смена версии модуля/provider'а или блока backend/`cloud` **требует** повторного запуска `init`.
* `.terraform/` — локальный кэш — никогда не коммитьте его, никогда не редактируйте вручную.
