# 6b. Describe state locking

> **Scope note:** Какие типы backend существуют и как их конфигурировать —
> в 6c. Локинг, специфичный для local backend (API системы/файлов), отмечен
> в 6a, но общее поведение локинга, описанное здесь, применимо к любому
> backend, поддерживающему локинг.

## Core Concept

Локинг state предотвращает одновременную запись в один и тот же state
двумя операциями Terraform, что могло бы его повредить. Локинг
**автоматический** для каждой операции, которая может записать state, и
**опциональный** — полностью зависит от того, реализует ли его backend.

## Behavior

- Локинг происходит незаметно — вы не увидите сообщения, если только
  получение лока не занимает дольше ожидаемого, в этом случае Terraform
  выводит статусное сообщение. Отсутствие сообщения **не** означает, что
  локинга не происходит.
- Если получение лока не удаётся, Terraform **останавливает** операцию; он
  не продолжает без лока.
- Локинг можно отключить для большинства команд с помощью `-lock=false`.
  Это не рекомендуется.
- Не все backend поддерживают локинг — проверяйте страницу документации
  каждого конкретного backend.

```bash
terraform apply -lock=false
```

## Force Unlock

Если лок не освобождается автоматически (напр. процесс упал, пропало
сетевое соединение), используйте:

```bash
terraform force-unlock LOCK_ID
```

- Terraform требует уникальный **lock ID** как nonce, чтобы вы могли
  нацелиться только на конкретный, известный лок — Terraform выводит этот
  ID при сбое операции локинга.
- Используйте `force-unlock` только чтобы снять **свой собственный**
  зависший лок. Принудительное снятие лока, который активно использует
  кто-то другой, может привести к конкурентным записям и повреждению state.

## Exam Quick Facts

- Локинг **автоматический**, вы не запускаете его вручную — вы можете
  только его *отключить* (`-lock=false`) или *принудительно снять*
  (`force-unlock`).
- `-lock=false` пропускает локинг только для этого единичного вызова
  команды; он не меняет никакую постоянную конфигурацию.
- `force-unlock` требует **lock ID**, показанный в выводе исходного сбоя —
  без него принудительно снять лок нельзя.
- Backend без поддержки локов просто вообще не выполняет локинг — никакой
  ошибки, никакого предупреждения при обычной работе, он просто не
  защищён.
- Неудачное получение лока полностью **останавливает** запуск; Terraform
  никогда молча не продолжает работу с заблокированным state.
